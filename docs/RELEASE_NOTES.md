# Windows 0.1.0a8 / macOS 0.5.1 — 起動・終了と文脈設定を整備

Mac版・Windows版に、アプリやWebサイトごとの話題と優先用語を補足できる任意設定を追加しました。話題は400文字、用語は1設定につき32語（各80文字）、設定は64件までです。アプリの識別子や取得できたサイトのドメインが完全に一致する場合に、認識の参考として使います。ページのタイトルからサイトを推測せず、入力先が不明な場合や保護された欄では補足しません。優先用語の登録による本文の一括置換は行いません。

設定がなくても、普段どおり入力できます。Windowsではメインパネルの「設定」から「アプリ・サイト別の文脈…」、Macでは「アプリ・サイト」タブから追加できます。Windowsのサイト情報取得は対応するChromium系ブラウザに限定し、Macでも情報を取得できた場合に使います。Macで情報の範囲を「アプリ名のみ」にしている場合は、サイト設定を使いません。通常入力で有効なサイト設定がない場合は、追加のサイト取得を行いません。

Macの音声編集は、画面とショートカットから外しました。既存の設定データと内部処理は保持し、通常の音声入力に集中できるようにしています。

## 起動・終了の設定

Mac版・Windows版のメインパネルの設定に「アプリ」欄をまとめ、「ログイン時に起動する」と「信楽を終了」を配置しました。Mac版は既存のログイン項目を使い、Windows版は現在のユーザーの起動登録を切り替えます。初めて使うときに自動起動を勝手に有効にはしません。メインパネルの×ボタンは、これまでどおりパネルを閉じる操作で、信楽は常駐を続けます。

終了はメニューバー・通知領域の終了メニューと同じ処理を使い、保持した文章は次回に引き継ぎます。Mac版では終了時に保留中の自動転記を取り消すようにもしました。

## 開発者向けの計測CLI

WAVファイルを録音速度で認識workerへ渡し、初字幕・停止後の待ち・CPU秒・ピークRSSを記録する開発用CLIを追加しました。比較した待機処理の2案は、速度や発話中のCPU・メモリの明確な改善を確認できず、停止待ちの悪化と大きな揺れも残ったため採用を見送り、本体の認識・字幕・パラメータを維持します。CLIは開発者向けに同梱し、手順と確認範囲は[ベンチマーク手順](BENCHMARK.md)と[計測条件](PERFORMANCE.md)に記載しています。

# 0.1.0a7 — 大ウィンドウのCtrl操作を整理

大ウィンドウでは、左Ctrlを短く1回押すと録音を開始し、もう1回押すと停止するようにしました。録音ボタンでも開始・停止できます。停止した文章は保持し、入力先への貼り付けは保留します。録音を再開すると、保持した文章に改行を入れて追記します。

左Ctrlを短く2回押すと、未転記の文章を入力先へ一度だけ貼り付けて大ウィンドウを閉じます。録音中なら先に停止し、最後の認識が確定するまで大ウィンドウを残します。OS標準の×ボタンは、録音中なら中止して閉じる操作で、自動では貼り付けません。大ウィンドウが開いていないときの2回押しは、これまでどおり大ウィンドウを呼び出します。

転記済みの本文を表示して閉じ直しても、2回押しでは再転記しません。「閉じて転記」ボタンは、表示中の文章をもう一度使いたい場合にも使えます。入力先を確認できない場合や送信に失敗した場合は、文章を保持して大ウィンドウを残すか再表示します。送信済みで反映を確認できない場合は、自動で再送しません。

確定・転記・モデル準備を待っている間も、左Ctrlを短く2回押すと、進行状態を確認する画面を開けます。新しい録音は処理が完了してから始めてください。稀にキーの呼び出しに反応しなくなる症状の根本原因は、まだ確定していません。

転記の診断ファイルpaste-diagnostics.jsonには、その起動後何回目の転記試行かと、準備完了からの経過時間も記録します。初回だけ転記されない症状を切り分けるための情報で、症状自体の原因はまだ確定していません。

小窓は左Ctrlを長押しして録音し、離すと確定して貼り付ける操作を維持します。キーは設定から変更できます。

認識モデル・ネイティブエンジン・ランタイムはa6と同じです。辞書・設定・保存済みログ・取得済みモデルは引き継ぎます。配布exeは引き続き未署名です。Windows実機での更新・録音キー・入力先への転記は確認が必要です。

[ダウンロードと導入](INSTALL.md)・[ビルド方法](BUILD.md)・[動作報告](https://github.com/k3peta/shigaraki/issues/new/choose)

# 0.1.0a6 — 履歴タブと停止後の待ち時間の改善

大ウィンドウに「履歴」タブを追加しました。保存済みの音声入力を新しい順に読み返し、本文や認識原文をコピーできます。ログはローカルに保持し、スクロールに合わせて少しずつ読み込みます。ファイル全体を最初に読み込まないため、大きなログが録音開始を妨げない構成です。詳しくは[履歴の使い方](HISTORY.md)を参照してください。

録音中の字幕は維持し、停止時には処理中の古い字幕計算を中断して最終認識を優先するようにしました。確定済みの区間は保持し、未確定区間は最後の音声サンプルまで認識します。これから話す言葉を予測する処理や、新しいモデルは追加していません。

MacのCPUによる合成音声の比較では、約10秒の素材で停止後の認識待ちの中央値が1.21秒から0.61秒になりました。一方、約15秒の素材では0.27秒から0.30秒で、改善していません。各条件3回の結果で、Windows実機での速度や、句読点補完・転記までの時間を保証する数値ではありません。[計測条件](PERFORMANCE.md)も確認してください。

辞書・設定・保存済みログ・取得済みモデルは引き継ぎます。配布exeは引き続き未署名です。Windows実機での導入・更新・実マイク・入力先への転記は確認が必要です。

[ダウンロードと導入](INSTALL.md)・[ビルド方法](BUILD.md)・[動作報告](https://github.com/k3peta/shigaraki/issues/new/choose)

# 0.1.0a5 — 初期辞書を共通のAI用語へ整理

初期辞書から大学名などの個人用語を外し、OpenAI、ChatGPT、Codex、Antigravity、Claude、Geminiの6語を収録しました。「アンチグラビティ」からAntigravityへの表記補正などに加え、Haasの認識候補にも使います。候補を渡しても、必ず正しく認識されるとは限りません。

各自が登録した辞書を優先し、既存の辞書・設定・ログ・取得済みモデルは保持します。以前の組み込み大学名だけを使っていた場合は、必要な語を「単語辞書」に登録してください。未登録の大学名がモデル自身の認識結果に出ることはありますが、信楽からの優先候補や自動置換には使わなくなります。

認識エンジン、モデル、録音・転記の操作はa4と同じです。配布exeは引き続き未署名で、Windows実機でのa5の導入・更新・音声入力は確認が必要です。

[ダウンロードと導入](INSTALL.md)・[ビルド方法](BUILD.md)・[動作報告](https://github.com/k3peta/shigaraki/issues/new/choose)

# 0.1.0a4 — Haas版を「信楽」として本流へ

アプリ名、起動用exe、スタートメニュー、Windowsのアプリ一覧を「信楽」に統一しました。Haasを使うこの版を、今後の信楽Windows版の本流とします。

Haasテスト版からはそのまま更新でき、辞書・設定・ログ・取得済みモデルを引き継ぎます。内部の保存先は互換性のため維持しています。旧方式版のアプリやデータは変更しません。同時には起動できません。

旧Haas名のショートカットを更新し、別アプリを指す既存の同名ショートカットは保持します。デスクトップに作成できなかった場合は、スタートメニューの「信楽」フォルダー内から起動できます。

音声認識モデルとストリーミング制御はa3と同じです。今回の変更は名称と更新・導入案内の整備です。配布exeにはまだコード署名がありません。SmartScreenとSmart App Controlの違い、利用者が確認した暫定手順と適用条件を[導入ガイド](INSTALL.md#windows-security)へ追記しました。Windows実機でのa4の導入・更新・削除は、引き続き確認が必要です。
